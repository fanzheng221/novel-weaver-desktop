# 可选语义检索与分发

## 背景与目标

基础应用默认关闭语义检索，不要求用户安装 Ollama 或下载模型。SQLite 全文和关键词检索继续可用；语义召回作为本机可选扩展。关闭扩展不修改正文、设定或已有索引。

## 方案

首次打开书架会显示可跳过的扩展入口；设置 → 模型接入中的“语义检索”面板可随时安装、连接已有 Ollama、关闭或重新启用，并更新当前书籍的索引。安装状态、启用意愿和运行可用性分开记录。安装需要联网，正文推理在本机进行。

自动安装目前支持 macOS 14+ Apple Silicon。运行时固定为 Ollama 0.33.3，下载官方 `ollama-darwin.tgz`，先核对字节数与 SHA-256，再解压到用户目录。模型使用 `qwen3-embedding:0.6b`，由 Ollama 校验模型层；最后运行真实 embedding 探针，通过后才启用。首次使用已有模型也必须通过探针。

安装保护线为 8 GiB 总内存、估计可用内存 1 GiB、可用磁盘 4 GiB。这些是当前产品的保守保护线，不是模型厂商公布的最低配置，也不保证大型书籍的速度。macOS 估计值包含部分可回收文件缓存；内存不足可关闭其他应用后重新检查。GPU 不作为安装门槛。其他平台显示不支持自动安装，已有 Ollama 可在原生向量库兼容的前提下通过探针接入。

本机状态默认位于 `~/.novel-weaver/semantic`，桌面和共享核心使用同一目录。托管运行时使用 `127.0.0.1:11435` 及独立模型目录，不修改用户已有的 11434 服务。关闭立即改变取消代号，并取消跨进程推理／索引任务；托管模型请求卸载，用户共享服务不停止。闲置模型保留期为 30 秒。文件保留以便再次启用；中断的运行时下载可重试，模型层可由 Ollama 复用。

embedding 每批最多四份文档，重建按批写入向量库，不累计整本书的向量矩阵。请求有 60 秒期限，超长输入明确失败，不静默截断。模型不可用时回退 SQLite，并暂缓 30 秒重试；暂时的模型错误不把仍有效的索引标记为损坏。模型、维度或查询指令变化仍需要重建索引。

## 使用方式

1. 正常安装并启动基础应用；不需要额外安装 Node 或 Ollama。
2. 书架选择“安装并启用语义检索”，或“暂不安装”。以后可从模型设置补装。
3. 已有 Ollama 的用户在面板展开“已安装 Ollama？”，先自行准备默认模型，再选择“检查并使用已有 Ollama”。
4. 打开书籍后，点击“更新本书语义索引”。正文变化后索引失效时仍使用关键词检索，可再次更新。
5. 在同一面板的“试一试 · 检索本书正文”输入情节描述或关键词，例如“有人把钥匙交给主角的那一幕”。结果显示场景标题、正式正文及本次实际使用的检索方式；未启用、索引缺失、过期或故障时，会说明回退关键词检索的原因。
6. 可填写“只查此故事序之前”排除后续剧情；留空搜索主连续体的全部正式正文。当前入口不搜索未批准设定和候选稿，也不自动把结果加入写作助手。它帮助回顾人物经历、定位伏笔线索和查阅正文证据；不能自动判断矛盾或代替审校。
7. 随时点击“关闭语义检索”；重新启用会再次检查模型，兼容且未过期的索引可以复用。

环境变量示例见根目录 `.env.example`，需要在启动进程前设置；应用不会自动加载 `.env`。`NOVEL_WEAVER_EXTENSION_DIR` 可用于隔离测试。已有 Ollama 的地址、模型、维度和查询指令支持相应环境变量；托管扩展使用固定默认模型配置。

打包命令：

```sh
pnpm --filter novel-weaver-desktop tauri build --bundles app
pnpm --filter novel-weaver-desktop exec node scripts/verify-bundle.mjs
```

打包使用官方独立 Node 22.18+（22.x），携带当前 Node 可执行文件及许可证，并检查它与 SQLite 原生模块能共同运行。macOS 拒绝依赖 Homebrew 等本机动态库的 Node。发布包不回退到系统 Node 或开发目录。必须在目标架构上安装依赖、构建；跨平台产物仍需各自在干净系统中验收。

## 注意事项与验证

本次没有数据库迁移。RPC v9 新增扩展状态、安装、连接已有服务、启停及索引重建方法；原有方法参数保持兼容。向量库改为可选依赖并延迟加载。旧版本保存的 BYOK embedding 槽位保留但不再显示为有效配置。

`verify-bundle.mjs` 在仓库外复制产物，移除测试副本中的向量依赖、清空 PATH、注入无效的可选模型配置，验证创建项目、SQLite 检索和重新打开。核心测试覆盖默认关闭、模块缺失、资源门槛、请求超时和关闭取消；界面测试覆盖硬件拦截、安装进度、取消、启停及窄窗口。

正式对外发布仍需开发者证书签名、公证及下载隔离属性下的验收；本地成功构建不能替代这些发布步骤。模型首次加载和长文本性能取决于机器负载；安装探针只是可用性检查。
